# 部署教學（給第一次用 GitHub 的人）

完成後你會得到：一個網址（`https://你的帳號.github.io/網站名稱/`），任何人用手機或電腦打開都能用；你更新資料時，網站會自動檢查並更新。

整件事分四段，第 1–2 段是網站本身，第 3–4 段是「回報錯誤」功能（可以晚點再做，不做也不影響其他功能）。

---

## 事前準備

- 一個 GitHub 帳號（https://github.com 免費註冊）。
- 這個資料夾裡的所有檔案（你收到的 zip，解壓縮即可）。
- 免費版 GitHub Pages 要求儲存庫是**公開（Public）**。網站內容本來就是公開的，沒有帳號或密碼資料，這沒有問題；但請確認你對資料內容有公開的權利，網站頁尾已標示「整理自老師講義與公開資料，僅供學習使用」。

## 第 1 段：把檔案放上 GitHub

1. 登入 GitHub，右上角 **＋ → New repository**。
2. Repository name 填一個英文名稱，例如 `tcm-herbs`。選 **Public**。**不要**勾選 Add a README。按 **Create repository**。
3. 在新頁面點 **uploading an existing file**。
4. 打開解壓縮後的資料夾，**全選裡面的所有東西**（包含 `index.html`、`css`、`js`、`data`、`docs`、`scripts`、`gas`、`icons` 等資料夾，以及 `.github` 資料夾），拖進瀏覽器視窗。
   - 注意：`.github` 在 Mac 與 Windows 會被當成隱藏資料夾。Mac 在 Finder 按 `Command + Shift + .` 顯示隱藏檔；Windows 在檔案總管「檢視」勾選「隱藏的項目」。**如果少了 `.github` 資料夾，網站不會自動部署。**
   - 如果拖曳資料夾沒有成功，改用 GitHub Desktop（https://desktop.github.com），把資料夾加入後 Publish。
5. 下方 Commit changes，按綠色的 **Commit changes**。

## 第 2 段：開啟 GitHub Pages

1. 在儲存庫頁面，點上方 **Settings**。
2. 左邊選 **Pages**。
3. **Build and deployment → Source** 選 **GitHub Actions**。
4. 點上方 **Actions** 分頁，會看到一個名為「檢查資料並部署」的流程正在跑（黃色圓點）。等它變成綠色勾勾（約 1–2 分鐘）。
   - 如果沒有自動跑：在 Actions 頁面點左邊「檢查資料並部署」→ 右邊 **Run workflow**。
5. 回到 **Settings → Pages**，上方會出現你的網址。打開它。

之後每次你修改檔案並 Commit，這個流程都會自動重跑：**資料檢查通過才會部署；沒通過，網站維持原本正常的版本**，並在 Actions 頁面用紅色叉叉告訴你哪個檔案哪裡錯（看「資料維護說明」第 4 節）。

> 這個流程裡的「檢查」會確認：JSON 語法、恰好 162 味、id 不重複、`ref_id` 都存在、分類與考點檔案裡的藥材 id 都存在。

## 第 3 段：建立「回報錯誤」的 Google 試算表與 Apps Script

回報功能的路線是：網站 → Google Apps Script（一小段程式，免費）→ 你的 Google 試算表。

1. 到 https://sheets.google.com 建立一份新的試算表，命名為「中藥網站回報」。
2. 在試算表上方選單點 **擴充功能 → Apps Script**。
3. 刪掉編輯器裡原本的內容，把本專案 `gas/Code.gs` 的**全部內容**複製貼上。按 💾 儲存。
4. 在編輯器上方的函式下拉選單選 **setup**，按 **執行**。第一次會要求授權：選你的帳號 →「進階」→「前往（不安全）」→ 允許。（這是因為這支程式是你自己寫入、尚未經 Google 審核；它只存取這份試算表。）
5. 回到試算表，會多一個「回報」工作表，有標題列，「狀態」欄有下拉選單（待處理、已確認、已修正、不處理）。
6. 回到 Apps Script，右上 **部署 → 新增部署作業**：
   - 左邊齒輪選 **網頁應用程式**
   - 說明：隨意填，例如「v1」
   - **執行身分：我**
   - **誰可以存取：所有人**
   - 按 **部署**，複製出現的 **網頁應用程式網址**（結尾是 `/exec`）。

> 「誰可以存取：所有人」代表任何人都能對這個網址送資料，所以程式裡有擋機器人的機制（隱藏欄位、字數檢查、每分鐘與每日上限）。它只能「新增一列」到試算表，不能讀取你的任何資料。

## 第 4 段：把網址貼回網站

1. 在 GitHub 儲存庫點開 `js/config.js`，按右上角鉛筆圖示編輯。
2. 找到這行：
   ```js
   reportEndpoint: '',
   ```
   把剛才複製的網址貼在引號中間：
   ```js
   reportEndpoint: 'https://script.google.com/macros/s/xxxxxxxx/exec',
   ```
3. 同一個檔案裡 `appVersion: '1'` 改成 `'2'`（改程式碼檔案時都要把這個數字加一，離線快取才會更新）。
4. 按 **Commit changes**。等 Actions 變綠色勾勾。
5. 打開網站，進任一藥材頁，按「回報錯誤」，送出一筆測試。到試算表的「回報」工作表看有沒有新增一列。

### 如果送出失敗

- 先確認網址是 `/exec` 結尾，不是 `/dev`。
- 修改過 `Code.gs` 後，必須到 Apps Script **部署 → 管理部署作業 → 鉛筆 → 版本選「新版本」→ 部署**，修改才會生效（網址不變）。
- 網站表單失敗時不會丟掉使用者輸入，並有「複製內容」按鈕，所以不會因此遺失回報。
- **誠實說明**：這個「從 GitHub Pages 網域送到 Apps Script」的流程，我在開發環境無法連網實測（只模擬了網站這一端的送出與錯誤處理）。表單採用最不容易被瀏覽器擋的送法（`text/plain`，不觸發預檢請求），一般可行，但請你照第 4 段第 5 步實際測一次。若測試失敗，請把瀏覽器開發者工具（F12）Console 的紅字貼給我。

### 選用：啟用 Cloudflare Turnstile（第一階段可不做）

如果之後發現有人亂送，再做：

1. 到 https://dash.cloudflare.com 註冊（免費）→ Turnstile → 新增網站，取得「網站金鑰」與「密鑰」。
2. 網站金鑰貼到 `js/config.js` 的 `turnstileSiteKey: ''`（並把 `appVersion` 加一）。
3. 密鑰**不要**放在 GitHub：到 Apps Script 左邊 **專案設定 → 指令碼屬性 → 新增**，名稱 `TURNSTILE_SECRET`，值貼上密鑰。
4. 重新部署 Apps Script（新版本）。

## 之後怎麼更新網站

| 想做的事 | 做法 |
|---|---|
| 改藥材資料 | 看 `docs/資料維護說明.md` |
| 換回報網址、改程式 | 改完把 `js/config.js` 的 `appVersion` 加一 |
| 看有沒有部署成功 | 儲存庫 → Actions 分頁，綠色勾勾＝成功 |
| 本機預覽 | `docs/資料維護說明.md` 第 6 節 |
| 回到上一個版本 | 儲存庫 → 該檔案 → History → 找到舊版 → 複製內容回去 |

## 常見問題

**網站是空白的／一直顯示「載入資料中」**：按 F12 看 Console 有沒有紅字。最常見是 `data/` 裡的某個 JSON 檔被改壞（多一個逗號、少一個引號）。到 Actions 頁面看檢查結果，會指出檔案。

**更新了資料但網站還是舊的**：先等 Actions 跑完（綠色勾勾）。有網路時網站會抓最新資料（GitHub 本身可能有幾分鐘的快取）；若剛離線再上線，重新整理一次。

**手機可以安裝成 App 嗎**：可以。用 Chrome 或 Safari 開啟網站，選「加入主畫面」。安裝後在沒有網路時，已載入過的資料仍可使用。
