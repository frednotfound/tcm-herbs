# 資料維護說明（不需要會寫程式）

所有藥學內容都在 `data/` 資料夾的 JSON 檔裡。**網站只負責顯示，不會自己補資料、不會自己推測。** 你改了 JSON 並 Commit，網站就會跟著變。

## 1. 每個檔案管什麼

| 檔案 | 內容 | 網站哪裡會用到 |
|---|---|---|
| `data/herbs.json` | 360 味藥材（常用中藥 162 味＋臺灣中藥典第五版增補 198 味，順序不變） | 幾乎所有頁面 |
| `data/general_theory.json` | 總論：本草、採集、炮製、性味歸經、配伍規則（十八反、十九畏、妊娠）、部位拉丁名 | 總論頁、配伍禁忌頁 |
| `data/categories.json` | 分類與各類概論；每類的 `herb_ids` | 分類概論頁 |
| `data/exam_highlights.json` | 小重點、考試方劑 | 目前只用於資料檢查；第二階段的「考點整理」頁會用 |
| `data/ingredient_taxonomy.json` | 成分分類樹（10 大類） | 成分樹反查、成分類別篩選、搜尋展開 |
| `data/alias_dictionary.json` | 別名、化合物同義詞、科別別名 | 搜尋、成分歸類 |
| `data/derived/part_groups.json` | **衍生**：使用部位原文 → 篩選分組（草稿，待你審核） | 使用部位篩選 |
| `data/compounds.json` | 化合物結構式對照（名稱 → `structures/*.svg`、SMILES、PubChem CID） | 藥材頁「成分」的結構圖 |
| `data/meta.json` | 資料版本、更新日 | 關於頁、回報表單 |

**原則**：`herbs.json` 是講義原文的整理，只改內容、不改欄位名稱。為了篩選或搜尋而需要的對照（分組、同義詞、分類樹），放在其他檔案，不要寫回 `herbs.json`。

## 2. 在 GitHub 網頁上改資料

1. 在儲存庫點進 `data/herbs.json` → 右上角鉛筆。檔案很大，用編輯器的搜尋（Ctrl/⌘ + F）找到藥名，例如 `"name_zh": "麻黃"`。
2. 改你要改的字。**只動引號裡面的文字**，不要刪掉引號、逗號、括號。
3. 把 `data/meta.json` 的 `data_version` 改成新的（例如 `2026-12-03.1`）、`updated` 改成今天日期。
4. Commit changes。到 **Actions** 看是否變綠色勾勾。綠＝已上線；紅＝網站維持舊版，點進去看錯誤訊息（第 4 節）。

> 想改很多筆，建議用 VS Code（https://code.visualstudio.com）在電腦上改，它會即時標出 JSON 語法錯誤。

## 3. 欄位速查（`herbs.json`，以防風為例）

（下面範例的 `//` 說明文字只是註解，真正的 JSON 裡不能寫。）

```json
{
  "id": "herb_fangfeng",          // 唯一編號，網址與連結都靠它。不要改、不要重複
  "name_zh": "防風",
  "aliases": [],                   // 別名，每個一個字串
  "name_latin": "Saposhnikoviae Radix et Rhizoma",
  "ed3_updated": true,             // true 會顯示「★3版」（常用中藥第三版修改）
  "category": "解表藥>辛溫解表藥",  // 大類>小類，用「>」分隔
  "properties": { "four_natures": [], "five_flavors": [], "meridians": [] },  // 沒資料就留空陣列，網站會顯示「未標示」
  "ingredients": [ { "category_raw": "Coumarins", "compounds": [ { "name": "Bergapten", "content_spec": null, "pharmacology": [], "note": null } ] } ],
  "effects": [ { "group": "一般", "items": ["祛風勝濕", "息風止痙"] } ],
  "herb_grade": "上品",            // 只能是 上品／中品／下品，沒有就 null
  "compatibility": { "xiang_xu": [], "shi": [], "wei": ["萆薢"], "wu": [], "fan": [], "sha": ["附子"], "taboo": [], "clinical_pairs": [] },
  "formulas": ["荊防敗毒散"],
  "related_herbs": [ { "name_zh": "炮薑", "relation": "不同炮製品", "ref_id": "herb_paojiang", "part_used": null, "notes": "…" } ],  // ref_id 有值時網站會連到該藥；沒有就填 null
  "tags": ["上品", "要藥", "第三版修改"],   // 小重點標籤；篩選用
  "images": [],                    // 照片預留，目前一律空陣列
  "source_page": [8]               // 講義頁碼
}
```

幾個容易踩的點：

- **沒資料請留空**（`[]` 或 `null`），不要寫「無」「不詳」。網站會自動顯示「未標示」或不顯示。
- `herb_grade` 與 `tags` 裡的「上品／中品／下品」是兩個地方，修改時兩邊一起改。
- 新增或刪除藥材時，除了 `herbs.json`，還要同步：`categories.json` 的 `herb_ids`、以及 `scripts/validate.mjs` 最上面的 `EXPECTED_HERBS = 360`（否則檢查會因為「不是 360 味」而擋下部署）。這個「必須恰好等於設定筆數」是刻意的保護，避免誤刪。
- 化合物名稱想讓「成分樹反查」歸得進去，不要改 `herbs.json`，改 `ingredient_taxonomy.json` 或 `alias_dictionary.json`（見第 5 節）。

## 4. 檢查失敗了怎麼辦

Actions 頁面點進紅色叉叉的那次執行 → 「validate」→ 展開「檢查資料」，會看到像這樣的訊息：

```
【錯誤】data/herbs.json 第 12 筆（麻黃／herb_mahuang）：缺少欄位 compatibility
【錯誤】data/herbs.json：應有 360 味，實際 359 味
【錯誤】data/herbs.json（桑寄生）：related_herbs 的 ref_id「herb_xxx」不存在
【錯誤】data/categories.json：JSON 語法錯誤：Unexpected token } in JSON at position 1234
```

照訊息指的檔案與藥名修正後再 Commit 即可。以「【提醒】」開頭的只是提示，不會擋下部署。

## 5. 常見維護工作

**審核使用部位分組**（`data/derived/part_groups.json`）  
這是我依關鍵字草擬的 90 種寫法對照，`"review": true` 的是寫法較複雜、特別需要你看的（約 34 筆），例如「乾燥果實（皂莢）；莖上之乾燥棘刺（皂角刺）」。每筆的 `groups` 是篩選分組，可選：根、根莖、皮、莖、葉、花、果實、種子、全草、菌核、其他。確認後把檔案上方的 `"status"` 改成 `"已審核"`，檢查就不再提醒。

**讓某個「未歸類」的成分歸進分類樹**  
網站的「成分 → 未歸類成分」頁會列出對不上的成分（數量以頁面顯示為準）。要歸類：
- 它其實是已有化合物的另一種寫法 → 到 `alias_dictionary.json` 的 `compound_synonyms` 加一組（`canonical` 是分類樹上的寫法，`aliases` 放這個寫法）。
- 它是新的化合物 → 到 `ingredient_taxonomy.json` 找到對的節點，把名稱加進該節點的 `compounds`。
- 它只是類別名（如「揮發油」「脂肪油」）→ 在樹上沒有對應節點，維持未歸類是正確的。

**新增別名**（搜尋「丹皮」要找到牡丹皮）  
`alias_dictionary.json` 的 `herb_and_char_variants`：`canonical` 放藥材在 `herbs.json` 的名稱，`aliases` 放別名。

**化合物結構式**  
`data/compounds.json` 每筆用 `name`／`aliases`／`match_names` 對應到藥材成分名稱，`svg` 指向 `structures/` 裡的檔案。同一個名稱若對到兩筆以上（例如不同立體異構），藥材頁會並排顯示並在縮圖下標出 PubChem CID；資料檢查會列出這些名稱提醒你確認。

**搜尋的簡體字**  
搜尋時會自動把常見的中藥簡體字轉成繁體（例如「麻黄」「当归」「生物碱」），對照表在 `js/lib/derive.js` 的 `S2T_PAIRS`。資料本身請一律使用繁體。

**放置藥材照片（第三階段）**  
目前 `images` 全為空陣列，網站不會報錯。到時照片放 `images/herbs/`，在 `images` 欄填路徑，會另外給你說明。

## 6. 在自己的電腦預覽

雙擊 `index.html` **不會**成功（瀏覽器基於安全理由不讓網頁直接讀本機的資料檔，網站會顯示「資料載入失敗」）。需要開一個小伺服器：

- 有裝 Python 3：在專案資料夾開終端機，執行 `python3 -m http.server 8000`，然後瀏覽器開 http://localhost:8000
- 或用 VS Code 的 Live Server 擴充功能，在 `index.html` 按右鍵 → Open with Live Server。

本機檢查資料（需 Node.js 22 以上，https://nodejs.org）：

```
node scripts/validate.mjs        # 資料檢查，與 GitHub 上跑的相同
node scripts/test_search.mjs     # 搜尋自我測試，會印出幾個範例搜尋結果
```

## 7. 網站不會做的事（刻意的）

- 不補寫、不推測藥理、成分、基原、劑量；不產生國考答案。
- 不修改你的原始資料。網站用到的「衍生」對照（使用部位分組、成分歸類）都另外存放，並在畫面上標示「衍生」。
- 配伍禁忌頁只呈現資料裡有的規則，沒命中不代表安全，頁面固定顯示「僅為課程整理，非臨床用藥依據」。
